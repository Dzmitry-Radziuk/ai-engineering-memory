# Локальные benchmarks

`benchmark_memory.py` измеряет FTS-поиск, `UserPromptSubmit` как для пустого project namespace, так и для заполненного (1% от числа global-записей), инициализацию актуальной схемы, миграцию v5, запись candidate, dedupe, запуск MCP и roundtrip поиска, backup и `restore --dry-run` на синтетических наборах 1k/10k/100k global-записей.

Последний локальный snapshot результатов: [Windows / Python 3.14](results/2026-10-24-windows-python-3.14.md).

Измерения выводятся в JSON в stdout. В отчёте есть параметры reference host, p50/p95/p99, размер основной SQLite-БД, доступность FTS5 и версия схемы. Если Windows отказывает в создании pipe дочернего процесса, метрики MCP явно помечаются как недоступные или частичные. Данные создаются в отдельной временной папке и удаляются после каждого размера; пользовательская база и проекты не используются.

Из корня репозитория:

```powershell
.venv\Scripts\python.exe -m bench.benchmark_memory
.venv\Scripts\python.exe -m bench.benchmark_memory --sizes 1000 10000 --iterations 25
```

Запуск 100k занимает больше времени и памяти. Результаты зависят от процессора, накопителя, файловой системы и сборки SQLite. Сравнивайте только отчёты с одинаковым размером базы и сопоставимыми host-параметрами; абсолютные цифры из разных машин не являются CI-регрессией.
