# Политика безопасности

## Поддерживаемые версии

Обновления безопасности в настоящее время готовятся для текущей ветки `main`.
Отдельные релизные ветки и перенос исправлений в старые версии не обещаны.
При сообщении укажите версию пакета или commit SHA, который вы проверяли.

## Как сообщить об уязвимости

Предпочтительный канал — **Security → Advisories → Report a vulnerability** в
GitHub, если приватная отправка отчётов включена для репозитория. Наличие этой
возможности зависит от настройки GitHub и этим файлом не подтверждается.

Если кнопки приватного сообщения нет, создайте публичный issue только с просьбой
предоставить приватный канал. Не публикуйте в issue детали эксплуатации,
рабочий proof of concept, секреты, персональные данные или содержимое баз памяти.

В приватном сообщении полезно указать:

- затронутую версию или commit;
- компонент и предполагаемое влияние;
- минимальные шаги воспроизведения на искусственных данных;
- возможное временное смягчение проблемы.

Не прикладывайте реальные пользовательские базы, конфигурации с секретами,
клиентские переписки, логи запросов или абсолютные локальные пути. Срок ответа и
исправления не гарантируется; maintainer подтвердит получение и согласует
дальнейшее раскрытие после проверки.
