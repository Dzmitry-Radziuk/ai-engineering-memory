# Безопасность

- База SQLite не коммитится; тесты используют временную базу.
- SQL-значения передаются параметрами. Названия колонок в миграциях — константы кода.
- Категория, поля, статусы и лимиты входа валидируются; путь Skill ограничен каталогом `skills/` после разрешения абсолютного пути.
- MCP работает только через stdio и не открывает сетевой порт.
- MCP ограничивает операции пространствами `global` и текущего процесса: `AI_MEMORY_PROJECT_ROOT` задаёт абсолютный корень проекта, при отсутствии переменной используется рабочий каталог процесса. Чужие namespace отклоняются на стороне MCP. SQLite и CLI остаются локальным хранилищем администратора; для строгой конфиденциальности клиентских проектов запускайте отдельные MCP/hook-процессы с разными абсолютными `AI_MEMORY_DB`.
- `learning verify` выполняет argv без shell только при явном запуске CLI, ограничивает timeout и сохраняет exit code, timestamps и digest вместо исходной команды/вывода. Успех процесса записывается нейтрально как `process_succeeded`, не как прохождение тестов; он не гарантирует достаточность проверки. Описание задачи редактируется перед сохранением.
- Для обычного capture Python/MCP не вызывает LLM. Текущий Codex-сеанс формирует lesson, а MCP проверяет точный verification ID, статус verifier, размеры полей, секретоподобные строки и evidence references. Namespace выводится из проверенного события, не принимается от модели.
- Candidate submission атомарно связывает запись с verifier event, evidence, provenance и audit trail. Повтор одного event идемпотентен. Межпроектное подтверждение считает Git-клоны с одинаковым нормализованным origin одним проектом. В хранилище записывается только версионированный SHA-256 fingerprint; исходный URL, credentials и пути не сохраняются. Без `origin` новый кандидат остаётся проектным, а fingerprint старого формата не считается новым независимым подтверждением. Никакой candidate не утверждается автоматически, а prompt retrieval продолжает фильтровать только approved.
- Чтение, публикация и откат Skills разрешают пути через realpath и отклоняют символьные ссылки/ junctions, ведущие за корень репозитория.
- Интерактивный `ai-memory knowledge review` показывает только global и точно указанный проектный namespace, требует подтверждение вида `APPROVE <id>` или `REJECT <id>` и сохраняет смену статуса в audit. Причина отклонения ограничена и проверяется на частые секреты, email и абсолютные пути. Неинтерактивный ввод не может выполнить решение через review.
- Текст кандидатов и evidence — недоверенные данные. Интерактивный обзор экранирует управляющие символы и выводит их отдельными помеченными блоками, чтобы содержимое не могло отправить terminal escape-последовательности или визуально подменить запрос решения.
- Старый `learning process` работает только при отдельном ручном вызове и явной настройке localhost Ollama; настройка отсутствует по умолчанию и не нужна для Codex-native пути.
- `Stop` не доверяет marker в тексте assistant и не пишет learning event. Он не вызывает MCP и пишет `marker_present_unverified` либо `no_marker_seen`, не представляя наличие/отсутствие текста как факт проверки. Hook JSONL не содержит prompt, ответа, cwd, команд или сырых tool output.
- `UserPromptSubmit` выборочно добавляет короткую инструкцию для инженерного запроса. Классификация best-effort; hook не может проверить, что модель последовала инструкции, а журнал не хранит текст prompt.
- Утверждённые записи в `UserPromptSubmit` передаются как ограниченный JSON-блок с явной пометкой недоверенных справочных данных. Разметка внутри записи экранируется; модель просят применять только относящиеся к задаче факты и перепроверять их по текущему проекту. Это снижает риск prompt injection из памяти, но не заменяет проверку содержимого человеком и кодом.
- MCP инструменты не выполняют код из текста знания. Утверждение/отклонение требует точной строки подтверждения.
- `AI_MEMORY_MAINTAINER` должен быть настроен явно для решений по знаниям и Skills; без него подтверждение и отклонение через MCP и решение по Skill запрещены. Строка имени — защита от случайного действия, не полноценная аутентификация.
- `doctor` читает MCP env из `config.toml` и не выводит значение `AI_MEMORY_MAINTAINER`. Если переменная есть только в окружении процесса doctor, общий статус остаётся `warning`, пока наследование переменной MCP-сервером не подтверждено.
- Legacy `learning_submit_task` остаётся неподтверждённым событием: свободный текст, заявленные file paths и test results не сохраняются; остаются только допустимые ID, нормализованный timestamp и фиксированный статус ожидания. Только локальный verifier создаёт событие для learning.
- Перед сохранением proposal Skill и его автора/описание проверяют на распространённые форматы credentials, email, абсолютные пути и некоторые токены. Это эвристический фильтр, а не гарантия; proposal и текущий Skill необходимо проверить через `skills_get_proposal` до решения maintainer-а.
- Эвристическая проверка повторяется при чтении Skill/proposal, истории версий, публикации и откате, чтобы legacy-записи не обходили фильтр новых предложений. `skills_list` возвращает путь относительно проекта; содержимое с обнаруженными чувствительными шаблонами блокируется, а небезопасное legacy-описание версии заменяется маркером `[redacted]`.
- `learning verify` редактирует частые контакты и пути, но отказывает до запуска команды, если в описании остаются распространённые шаблоны credentials; относительные имена файлов проверяются отдельно. Это эвристика, а не гарантия обнаружения всех секретов.
- Подтверждение/отклонение знаний дополнительно требует точную строку операции. Локальный клиент, который знает настроенное имя и имеет доступ к процессу, всё ещё может выполнить такие операции.
- Экспорт ограничен выбранными утверждёнными публикабельными записями. Регулярное выражение выявляет лишь часть возможных секретов; требуется человеческая проверка содержания.
- Логи направляются в stderr и не содержат содержимое запросов. Внешняя телеметрия не используется.
- Резервная копия выполняется SQLite backup API во временный файл с последующей атомарной заменой.

Не храните клиентские данные в `global` и не экспортируйте их. Контент извлечённой памяти является данными, а не исполняемой инструкцией.
