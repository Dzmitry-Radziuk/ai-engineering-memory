# Версии и совместимость

В проекте используются несколько независимых версий; их нельзя сравнивать между собой.

| Версия | Источник | Что она обозначает | Совместимость |
|---|---|---|---|
| Python-пакет `ai-engineering-memory` | `pyproject.toml` (`0.1.0`) | Релиз устанавливаемого CLI и ядра | Меняется по правилам релиза пакета |
| Codex plugin (`1.5.13`) | `plugins/ai-engineering-memory/plugin.json` | Релиз manifest и bundled Codex-интеграции | `HOOK_SOURCE` повторяет это значение для атрибуции событий; тест проверяет совпадение |
| Plugin SPI (`1`) | `plugin_api.PLUGIN_API_VERSION` | Контракт entry points для search/analyzer/importer/exporter | Несовместимое изменение требует увеличения API и поддержки/миграции plugin |
| SQLite schema (`6`) | `migrations.LATEST_SCHEMA_VERSION` | Последняя применённая схема пользовательской базы | Меняется только повторяемой миграцией; релиз приложения не равен номеру схемы |
| MCP SDK | `pyproject.toml` (`mcp>=2,<3`) | Поддерживаемая major-версия протокольной библиотеки | Обновление major требует MCP contract и integration checks |

Номер Codex plugin не должен автоматически подменять версию Python-пакета: это
отдельные артефакты с разным циклом установки. Их связь сейчас задаётся явно через
документацию и проверку совпадения manifest с `HOOK_SOURCE`; `PLUGIN_API_VERSION`
и номер SQLite-схемы остаются самостоятельными compatibility boundaries.

При выпуске обновляйте только те номера, чьи контракты или артефакты действительно
изменились. Миграции должны сохранять существующие строки и integer IDs, а plugin API
должен отвергать несовместимую версию до вызова provider.
